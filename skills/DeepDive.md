# PaperTrace · Paper-to-Page Skill

把一篇 ML 论文变成 PaperTrace 交互式精读页面的完整流程。

---

## 0. 快速检查：这篇论文适合精读吗？

精读一篇论文在开始之前先问自己三个问题：

- 这篇论文解决了一个**清晰定义的问题**吗？（方法类 > 综述类）
- 核心机制能用**具体例子**演示吗？（数学 + 可视化潜力）
- 这篇在领域里有**承上启下的位置**吗？（能接上已有的精读）

三个都是 yes → 开始。否则优先考虑放在 daily 推荐而不是完整精读。

---

## 1. 第一遍：定位论文

目标：搞清楚"这篇论文在干什么"，不要进细节。

**读什么：**
- Abstract 全文
- Introduction 第一段和最后一段
- Conclusion 全文
- 所有 Figure 和 Table（只看 caption）

**输出：**
```
问题：[这篇论文要解决什么问题]
已有方法的局限：[前人怎么做，差在哪]
核心贡献：[这篇做了什么，用一句话]
结果：[主要数字，在什么 benchmark 上]
```

**Prompt 模板（用 Claude 辅助）：**
```
请帮我分析这篇论文：[粘贴 abstract]

输出以下内容：
1. 核心问题（一句话）
2. 已有方法的核心局限
3. 这篇的核心贡献（一句话，不要 jargon）
4. 最重要的实验结果（1-2 个数字）
5. 与哪些已有工作关系最密切
```

---

## 2. 第二遍：拆解方法

目标：搞清楚"它具体怎么做"，能用自己的话复述每个公式。

**按这个顺序读：**
1. Method / Approach 全部
2. 所有带编号的公式——每个公式写下"这在说什么"
3. Algorithm box（如果有）
4. Ablation study——看哪些设计选择真正重要

**公式拆解模板：**
```
公式：[LaTeX]
这在说什么：[用大白话描述]
每个符号：
  - x_t：[是什么]
  - θ：[是什么]
  - ...
为什么这样设计：[直觉解释]
如果去掉这一项会怎样：[作者 ablation 说了什么]
```

**核心问题清单（边读边回答）：**
- [ ] 输入是什么？输出是什么？
- [ ] 训练 loss 是什么？优化什么？
- [ ] 推理时怎么生成？
- [ ] 和 baseline 最本质的区别在哪一步？
- [ ] 有没有 trick 藏在附录里？

---

## 3. 设计页面结构

PaperTrace 页面的标准 Section 顺序：

```
TL;DR                    ← 3 句话，非专家能看懂
架构总览卡片              ← 视觉化的问题→洞察→方法→结果
1. 背景与动机             ← 为什么这个问题重要，前人差在哪
2. 核心方法（可能多个 section）
   前向过程 / 训练目标 / 推理算法
   每个 section 必须有：公式 + 具体数字例子
3. [可选] 交互式 Widget   ← 参见 Section 5
4. 架构细节               ← 对比表格（和 baseline 逐项比较）
5. 实验与结果             ← 关键数字，不要全贴，选最重要的
6. 局限性与未来工作        ← 诚实，不要回避
7. 与其他工作的联系        ← 承上启下，接上 PaperTrace 已有精读
8. 补充资源               ← arXiv / GitHub / 相关精读链接
```

**TL;DR 写法：**
```
[论文名] 将 [任务] 视为 [核心框架]：
[前向过程/问题设定一句话]。
[逆向过程/核心方法一句话]。
扩展到 [规模] 后，在 [benchmark] 上可与 [baseline] 媲美。
```

**架构总览卡片模板：**
```
问题：[AR/旧方法] 有 [X] 局限
↓
洞察：[核心思路，一句话]
↓
前向过程：[怎么加噪声/定义问题]
↓
逆向过程：[怎么去噪声/生成答案]
↓
设计选择：[架构细节]
↓
如何学习：[训练目标]
↓
如何生成：[推理算法]
↓
结果：[关键数字]
```

## 4. 写具体例子（最重要的一步）

**每个核心公式都必须配一个具体例子。** 这是 PaperTrace 和普通精读的核心差异。

**例子设计原则：**
- 用最简单的输入：4–6 个 token，2–3 个 block，小数字
- 把每一步的中间结果都写出来，不要跳步
- 数字要对得上公式（哪怕是手算的近似）
- 如果有多个步骤，用逐步展开的格式

**具体例子的 Prompt：**
```
这是论文的核心公式：[公式]

请用这个句子做一个完整的 step-by-step 例子：
"The cat sat on the mat"（6 个 token）

要求：
- 展示每一个中间变量的具体数值
- 数字可以是合理的近似
- 不要跳步，每一步都写清楚在做什么
- 最后验证结果和公式对应
```

**例子质量检查：**
- [ ] 一个不懂这篇论文的人能跟上吗？
- [ ] 每个符号在例子里都有对应的具体值吗？
- [ ] 例子的结论和公式的含义一致吗？

## 5. 设计交互式 Widget

什么时候值得做 Widget：
- 有多个步骤可以"点击下一步"展示
- 有参数（t、block size、置信度阈值）可以拖动
- 有矩阵/表格需要高亮某一行来解释

**三种常用 Widget 类型：**

### 5.1 步骤导航器（最常用）
```
适用于：denoising 过程、生成步骤、算法 step-by-step
结构：
  - 顶部：dot 导航（● ○ ○）
  - 中间：token 可视化（颜色编码状态）
  - 底部：当前步骤的文字解释
  - 按钮：← 上一步 / 下一步 →
```

### 5.2 可点击矩阵
```
适用于：attention mask、关系矩阵
结构：
  - 矩阵：点击某行高亮显示
  - 右侧/下方：解释该 token 的访问视野
  - 图例：颜色 → 含义
```

### 5.3 参数滑动器
```
适用于：展示超参对结果的影响
结构：
  - slider：控制参数
  - 实时更新：公式结果/可视化
  - 说明：这个参数控制什么
```

**Widget 颜色规范（和 PaperTrace 保持一致）：**
```
已完成/高置信度：teal  (#E1F5EE / #9FE1CB)
警告/低置信度：  amber (#FAEEDA / #FAC775)
被重置/错误：    coral (#FAECE7 / #F5C4B3)
最终确认：       green (#EAF3DE / #C0DD97)
遮盖/待处理：    gray  (var(--color-background-secondary))
```

## 6. 写"与其他工作的联系"

这个 section 是 PaperTrace 的核心价值之一——帮读者建立知识图谱。

**格式：**
```
### [相关论文名]
[一句话：这篇和当前论文的关系是什么]
详细说明：[当前论文 cite 了它 / 改进了它 / 被它改进 / 同期工作]
在 PaperTrace 上查看：[内链]
```

**关系类型：**
- 理论基础：当前论文的数学推导来自哪里
- 解决局限：当前论文解决了哪篇的问题
- 被解决：哪些后续工作改进了当前论文
- 同期竞争：同一时期解决同一问题的其他方法

---

## 7. 质量检查清单

发布前逐项确认：

**内容**
- [ ] TL;DR 不包含 jargon，非专家能看懂
- [ ] 每个核心公式都有具体数字例子
- [ ] 具体例子的数字和公式对得上
- [ ] 局限性诚实，没有回避已知问题
- [ ] "与其他工作的联系"至少 3 篇

**可读性**
- [ ] 每个 section 开头有一句"这一节在做什么"
- [ ] 公式里的每个符号都有解释
- [ ] 没有未解释的缩写（第一次出现时展开）

**交互**
- [ ] Widget 在深色模式下正常显示
- [ ] 所有按钮可以点击
- [ ] 公式用 KaTeX 渲染，不是纯文本

**链接**
- [ ] arXiv 链接
- [ ] GitHub 链接（如果有）
- [ ] 相关 PaperTrace 精读内链

## 8. 时间分配参考

| 阶段 | 时间 | 产出 |
|------|------|------|
| 第一遍定位 | 15 min | 4 个问题的答案 |
| 第二遍拆解 | 1–2 h | 公式笔记 + 核心问题清单 |
| 设计结构 | 30 min | Section 大纲 |
| 写具体例子 | 1–2 h | 每个核心公式一个例子 |
| 写正文 | 1–2 h | 完整 markdown |
| 做 Widget | 1–2 h | 1–2 个交互组件 |
| 质量检查 | 30 min | 清单全部打勾 |
| **总计** | **5–9 h** | **一篇完整精读** |

## 9. 投稿者指南（社区贡献）

如果你想为 PaperTrace 贡献一篇精读：

1. 在 GitHub Issue 里先 claim 这篇论文（防止撞车）
2. Fork repo，在 `/papers/[arxiv-id]/` 下创建文件
3. 按本 skill 的结构写，至少完成 Section 1–5 和质量检查
4. 提 PR，标题格式：`[Paper] 论文名 (arXiv XXXX.XXXXX)`
5. 维护者会在 3 个工作日内 review

**最低要求（最小可发布单元）：**
- TL;DR + 架构总览 + 至少 2 个 section + 1 个具体例子
- 不需要 Widget（但有的话加分）

## Prompt 速查表

```
# 1. 定位论文
"分析这篇论文的核心问题、局限、贡献、结果：[abstract]"

# 2. 拆解公式
"用'The cat sat on the mat'举一个 step-by-step 的例子来解释这个公式：[公式]"

# 3. 生成 TL;DR
"用 3 句话写这篇论文的 TL;DR，要求：非专家能看懂，不用 jargon"

# 4. 写局限性
"这篇论文有哪些局限性？包括作者自己承认的和作者没提但读者应该知道的"

# 5. 找相关工作关系
"这篇论文和以下工作的关系是什么：[列出相关论文]"

# 6. Widget 代码生成
"帮我做一个步骤导航器 Widget，展示以下过程的每一步：[描述]
颜色规范：teal=完成，amber=低置信度，coral=重置，green=最终"
```
